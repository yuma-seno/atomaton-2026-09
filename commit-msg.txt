docs: atomaton is the agent a person reaches first

The three definitions that ship read as peers, and they are not. A person
describes what they want and `atomaton` decides what that is -- a question to
answer, one leaf to do, or work to split into sub-issues. `engineer` and
`reviewer` are the agents it and each other hand work to.

That was true of the prompt and nowhere in what a person reads. The shipped
README's table said it once; the root README, setup, the agents overview and
"what starts a run" all listed the three side by side, and the example in the
last of those named `/engineer`. So the four places a person actually starts
from now say which agent to ask, and the example asks that one.

The prompt itself changes with it. `atomaton` was the coordination layer and
nothing else -- `files_readonly`, no shell, "you never edit code". It is now the
front agent: it has `files` and `shell` and the same delivery path the engineer
has, and when the issue in front of it is already one leaf it does the work
rather than manufacture a child that restates it. The decomposition policy is
unchanged, because that is what keeps a task that is really three tasks from
becoming one pull request that is three changes.

The definitions are a template rather than a fixed set, and that is now said
where a person would look for it: adding an agent is a new file, adding a skill
is a new file, and nothing counts or names them outside the files themselves.
Two task pages say how, and the shipped README lists what arrives.
